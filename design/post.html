做一个打开就能玩的小游戏站

不需要注册，也不需要等构建。用最简单的方式，把「玩一会儿」这件小事做好。

项目简介
「玩一会儿」· 零后端、零构建的静态小游戏聚合站
语言
JavaScript
主要技术
HTML / CSS / JavaScript · Docker · Caddy

有时候，我只是想在两件事之间玩一局 2048，或者和朋友下盘五子棋。不想下载 App，不想登录，更不想先看一段广告。于是有了这个小项目：把游戏放在一个页面里，打开就玩。

01. 先把事情做简单

little-play-arcade 把五子棋、2048、扫雷、国际象棋和儿童益智小游戏放在一起。它不是一个庞大的游戏平台，而是浏览器里的一小块休息区。

对于这样的工具，简单本身就是功能。我希望它做到：

  • 低门槛：一个链接就能进入，不让准备工作打断兴致。
  • 容易部署：静态文件即可运行，不额外维护数据库或 API 服务。
  • 便于修改：用熟悉的 HTML、CSS 和 JavaScript，让小改动保持轻量。

不是每个小想法，都需要从一套复杂的技术栈开始。先让它有用，再决定它需要多复杂。

02. 零构建，不代表零设计

没有构建步骤，意味着源码和交付物之间少了一层转换。调整页面后，刷新浏览器就能看到结果。但目录组织、交互一致性和移动端体验，依然值得认真对待。

把部署也变成一件小事

静态站点很适合交给 Caddy 提供服务，再用 Docker 统一运行环境。下面是一个最小配置示意，用于说明静态文件的服务方式，并非仓库的完整部署配置：

Caddyfile示意配置
# 将静态站点目录挂载到 /srv
:80 {
    root * /srv
    encode gzip
    file_server
}

核心只有两件事：用 root 指定站点目录，用 file_server 提供静态文件。真正上线时，还需要根据访问方式配置域名、端口和持久化目录；请以仓库 README 为准。

03. 好玩，也要好用

游戏本身之外，我更关心第一次打开它的人会不会迷路。下一轮体验检查，可以从三个简单的问题开始：

  1. 能否一眼找到自己想玩的游戏？
  2. 在手机上，按钮是否好点、棋盘是否清楚？
  3. 结束一局之后，能否轻松重来或返回首页？

小项目的乐趣在于，每一次微小的改进都能立刻被感受到。如果你也想找个地方「玩一会儿」，欢迎来试试；遇到问题，也欢迎在 GitHub 留下反馈。
